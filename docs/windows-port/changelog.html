Commit 5: Focus & Repaint Fixes

c867d7c98 + (this commit)

Bugs Fixed

  • FIX Keyboard focus stuck on newest pane — Clicking an older split pane did not move keyboard focus to it. WS_CHILD windows require an explicit SetFocus(hwnd) on mouse click. Added the call in the WM_LBUTTONDOWN/WM_MBUTTONDOWN handler of surfaceWndProc.
  • FIX Closed pane leaves stale pixels — After a surface was destroyed, the parent window area it occupied retained old content until another pane was clicked. Fixed by calling InvalidateRect(hwnd, null, TRUE) on the main window after updateLayout() in closeSurface().

Cleanup

  • Removed debug log.info calls from closeSurface(), .quit performAction, and WM_CLOSE handler.

Files Modified

  • MOD src/apprt/win32/Surface.zig — added SetFocus(hwnd) in WM_LBUTTONDOWN/WM_MBUTTONDOWN
  • MOD src/apprt/win32/App.zig — added InvalidateRect after closeSurface layout update, removed debug logging

Commit 4: Surface Close, Tab Bar Fix, ConPTY Crash Fix

179d68a75

Features Added

  • NEW App.closeSurface() — removes a single surface from its tab's split tree; closes the tab only when empty, quits only when last tab closes
  • NEW App.tabContainsSurface() — recursive helper to locate a surface in a tab's split tree
  • NEW WM_CLOSE_SURFACE — custom Win32 message (WM_USER+2) posted by Surface.close() and dispatched in wndProc to defer surface destruction

Bugs Fixed

  • FIX Exit crashes entire app — Typing exit in a shell pane crashed the whole process. Root cause: the IO reader thread's ReadFile on the ConPTY output pipe returns ERROR_BROKEN_PIPE when the child exits, which hit an unreachable. Fixed by handling .BROKEN_PIPE to exit the read thread gracefully (src/termio/Exec.zig).
  • FIX Surface.close() was a no-op — Previously did nothing (TODO stub). Now posts WM_CLOSE_SURFACE to the main window, passing the surface pointer via wParam. This defers destruction to after tick() completes, avoiding use-after-free.
  • FIX .closed handler set app.running=false — The .closed return from keyCallback in Surface.zig was setting app.running = false, immediately quitting the app. Changed to a no-op since the core already calls rt_surface.close() before returning .closed.
  • FIX Tab bar hidden after switching — Switching from a multi-tab state back to the first tab didn't update layout. Fixed by calling updateLayout() in gotoTab().

Files Modified

  • MOD src/apprt/win32/App.zig — added WM_CLOSE_SURFACE constant, closeSurface(), tabContainsSurface(), WM_CLOSE_SURFACE handler in wndProc, updateLayout in gotoTab
  • MOD src/apprt/win32/Surface.zig — implemented close() with PostMessageW, changed .closed handler from app.running=false to no-op
  • MOD src/termio/Exec.zig — added .BROKEN_PIPE handler in threadMainWindows ReadFile error switch

  • MOD src/renderer/Thread.zig — Win32 surface type

Core Features at Launch

  • GPU-accelerated OpenGL 4.3+ rendering via WGL + GLAD
  • ConPTY-based terminal sessions (PowerShell, cmd.exe)
  • Multiple tabs with GDI-drawn tab bar
  • Horizontal and vertical split panes
  • Incremental search with Escape/Enter handling
  • Clipboard support (CF_UNICODETEXT)
  • Full keyboard input with scancode translation
  • Mouse input (click, scroll, movement tracking)
  • Window title updates via OSC escape sequences
  • Config file support (%LOCALAPPDATA%\ghostty\config.ghostty)

Known Limitations

  • DPI awareness not implemented (getContentScale returns 1.0)
  • wglMakeCurrent warning during shutdown (non-fatal)
  • Single window only (new_window creates a tab instead)

Pre-Implementation: Research & Design

Research Phase

Before any code was written, extensive research was conducted into:

  • Ghostty's architecture — apprt interface, core/renderer separation, config system
  • Win32 windowing — WNDCLASSEXW, message loop, child windows, WM_COMMAND routing
  • WGL OpenGL — per-window device contexts, pixel format, context creation, GLAD integration
  • ConPTY — Windows pseudo-terminal API, integration with existing src/pty.zig
  • Font backends — DirectWrite availability, existing font discovery in Ghostty
  • Existing Windows support in the codebase — pty.zig, os/windows.zig, renderer hooks

The design document (design.html) captures the full analysis.

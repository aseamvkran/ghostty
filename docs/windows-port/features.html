Implementation detail: Each menu item has a unique command ID (CMD_COPY = 100, CMD_PASTE = 101, etc.). When a menu item is clicked, WM_COMMAND delivers the ID via LOWORD(wParam). handleMenuCommand() matches the ID and calls the appropriate action.

Comptime note: The menu bar creation uses many utf8ToUtf16LeStringLiteral calls at comptime, which exceeds Zig's default 1000-branch limit. @setEvalBranchQuota(50000) is set at the top of createMenuBar().

2. Tab Management

Tabs are rendered as a custom GDI-drawn tab bar at the top of the window. The tab bar is 30px tall and only shown when there are 2+ tabs.

How Tabs Work

  • Each tab is a Tab struct containing a root SplitNode, a focused surface pointer, and a title
  • Only the active tab's surfaces are visible — other tabs' surfaces are hidden via ShowWindow(SW_HIDE)
  • Tab titles come from the terminal's OSC title escape sequence
  • The tab bar is painted in WM_PAINT using FillRect and TextOutW
  • Tab clicks are detected in WM_LBUTTONDOWN by checking if Y < 30px and computing tab index from X

Tab Actions

New TabCreates a surface, wraps it in a Tab, appends to list, switches to it

Goto TabSwitches active_tab index, hides old tab's surfaces, shows new tab's, relayouts

Close Tabs RightCloses all tabs to the right of the active one

3. Split Panes

Within each tab, panes are managed as a binary tree of SplitNode values.

Split Tree Structure

// A tab with 3 panes arranged as:
//   [  A  |  B  ]
//   [     C     ]
SplitNode::split {
    direction: .vertical,
    ratio: 0.5,
    first: SplitNode::split {
        direction: .horizontal,
        ratio: 0.5,
        first: SplitNode::leaf(A),
        second: SplitNode::leaf(B),
    },
    second: SplitNode::leaf(C),
}

Operations

  • Split: Find the focused leaf → replace it with a split node containing the old surface + new surface
  • Remove: Find the surface's leaf → replace the parent split with the sibling → collapse
  • Layout: Recursively divide the available rectangle along each split's direction/ratio, call MoveWindow on leaves
  • Equalize: Recursively set all ratios to 0.5
  • Navigate: Collect all leaves in-order, find the focused one, move prev/next

4. Search with Match Count

The search bar is a Win32 EDIT control with a companion STATIC label showing the match count.

Layout

┌──────────────────────────────────────────┬──────────┐
│  EDIT (search text input)                │  3/42    │
│  WS_CHILD | WS_BORDER | ES_AUTOHSCROLL  │  STATIC  │
│  full width minus 100px                  │  100px   │
└──────────────────────────────────────────┴──────────┘

Search Flow

  1. User triggers search (Edit → Find, or keybinding)
  2. showSearch() → shows EDIT + STATIC, focuses EDIT
  3. User types text → EN_CHANGE notification → handleSearchInput()
  4. Input is read as UTF-16, converted to UTF-8, sent to core via performBindingAction
  5. Core searches the terminal buffer, sends back .search_total and .search_selected actions
  6. updateSearchCount() formats "X/Y" and updates the STATIC label
  7. User presses Enter → navigates to next match (or Shift+Enter for previous)
  8. User presses Escape → hideSearch() hides the bar, returns focus to surface

Key Interception

The search EDIT control is a standard Win32 control that processes its own WM_KEYDOWN messages before the parent window sees them. To handle Escape and Enter, the main message loop intercepts these keys before TranslateMessage/DispatchMessageW when the message target is the search EDIT.

5. Fullscreen

Fullscreen is toggled via F11 or the Window → Fullscreen menu item.

Enter Fullscreen

  1. Save current window style: GetWindowLongPtrW(GWL_STYLE)
  2. Save current window rect: GetWindowRect()
  3. Remove caption and thick frame from style
  4. Get monitor bounds: MonitorFromWindow(MONITOR_DEFAULTTONEAREST) → GetMonitorInfoW()
  5. Position window to fill monitor: SetWindowPos() with SWP_FRAMECHANGED

Exit Fullscreen

  1. Restore saved window style: SetWindowLongPtrW(GWL_STYLE)
  2. Restore saved position/size: SetWindowPos() with saved rect

6. Float on Top

Toggled via Window → Float on Top. The menu item shows a checkmark when active. Uses SetWindowPos with HWND_TOPMOST to make the window stay above all others, and HWND_NOTOPMOST to restore normal Z-ordering.

7. Right-Click Context Menu

When a surface receives WM_RBUTTONDOWN, the click is first passed to the core (for mouse reporting). If not consumed, the parent App creates a popup menu with Copy/Paste/New Tab/Close Tab and shows it via TrackPopupMenu with TPM_RETURNCMD to get the selected item synchronously.

8. Keyboard Input

Key Translation Pipeline

WM_KEYDOWN (scancode in lParam)
    ↓
translateScancode() → Ghostty key enum
    ↓
PeekMessage(WM_CHAR) → UTF-16 text
    ↓
GetKeyState() → modifier flags (shift, ctrl, alt, caps)
    ↓
core_surface.keyCallback(key, text, mods)
    ↓
Core processes: binding match → terminal write

Special Cases

  • Alt+Key (WM_SYSKEYDOWN): Handled to prevent Win32 system menu activation
  • Dead keys: WM_CHAR provides the composed character
  • Extended keys: Bit 24 of lParam distinguishes left/right Ctrl, numpad Enter, etc.
  • F11: Intercepted by the surface for fullscreen toggle

10. Clipboard

Copy (read from terminal)

  1. Core provides text via setClipboard()
  2. OpenClipboard → EmptyClipboard
  3. Allocate global memory: GlobalAlloc(GMEM_MOVEABLE)
  4. Copy UTF-16 data to global memory
  5. SetClipboardData(CF_UNICODETEXT) → CloseClipboard

Paste (write to terminal)

  1. OpenClipboard → GetClipboardData(CF_UNICODETEXT)
  2. GlobalLock → read UTF-16 → GlobalUnlock
  3. Convert UTF-16 to UTF-8 → send to core
  4. CloseClipboard

Hot Reload

The Ghostty → Reload Configuration menu item re-reads the config file from disk and replaces the active config. No restart required. Font, theme, and other visual changes take effect immediately.

Testing Strategy

Challenge

The Win32 apprt modules (App.zig, Surface.zig) depend on Win32 API calls (CreateWindowExW, MoveWindow, WGL functions, etc.) that require a running Windows desktop environment with HWNDs. This makes them impossible to unit test in a pure headless environment.

Solution

Tests focus on the pure logic that doesn't require Win32:

  • Split tree management: Create/split/remove nodes, tree structure validation
  • Equalize algorithm: Verify ratio resetting across nested trees
  • Search count formatting: Pure string formatting logic matching App.updateSearchCount

Mock surfaces use properly aligned pointer addresses via @ptrFromInt(@alignOf(Surface) * (id + 1)). The split tree only stores and compares pointers — it never dereferences them during tree operations.

Mock Surface Technique

Real Surface objects require HWNDs and WGL contexts. Tests use mock pointers:

fn mockSurface(id: usize) *Surface {
    // Use properly aligned addresses to satisfy Zig's safety checks
    return @ptrFromInt(@alignOf(Surface) * (id + 1));
}

Why this works: The split tree only stores and compares surface pointers. It never dereferences them during tree operations (split, remove, equalize, find). Layout is the one function that dereferences (to call MoveWindow), but tests skip layout.

Why @alignOf * (id + 1): Zig's safety checks validate pointer alignment. Simple @ptrFromInt(id) would fail because id=0 is null and other ids wouldn't be properly aligned for the Surface struct.

Search Count Format Function

Tests include a standalone formatSearchCount() function that replicates the formatting logic from App.updateSearchCount(). This lets us test the formatting without needing a real HWND for the STATIC control.

fn formatSearchCount(buf: []u8, total: ?usize, selected: ?usize) []const u8 {
    if (total) |t| {
        if (selected) |s| {
            return std.fmt.bufPrint(buf, "{d}/{d}", .{ s + 1, t }) catch "";
        } else {
            return std.fmt.bufPrint(buf, "0/{d}", .{t}) catch "";
        }
    }
    return "";
}

Test Infrastructure

Tests are integrated into the Zig build system through:

  1. src/apprt/win32.zig exports Tab_test via @import("win32/Tab_test.zig")
  2. The test block in win32.zig uses @import("std").testing.refAllDecls(@This())
  3. This causes the Zig test runner to discover and execute all tests in Tab_test.zig
  4. Tests use std.testing.allocator for leak detection

Layout System

The updateLayout() function computes the content area by subtracting the tab bar (30px, only shown when >1 tab) and search bar (30px, only when active) from the client rect. The search bar is split into the EDIT control (full width minus 100px) and the count label (100px, right-aligned). The remaining area is passed to Tab.layout() for recursive split positioning.

Input Handling

The surface's surfaceWndProc handles:

  • WM_KEYDOWN/WM_KEYUP/WM_SYSKEYDOWN/WM_SYSKEYUP — keyboard input with PeekMessage for WM_CHAR
  • WM_LBUTTONDOWN/WM_MBUTTONDOWN — left/middle mouse button
  • WM_RBUTTONDOWN — right-click (core first, then context menu if not consumed)
  • WM_MOUSEWHEEL/WM_MOUSEHWHEEL — vertical and horizontal scroll
  • WM_MOUSEMOVE — cursor tracking
  • WM_SETFOCUS/WM_KILLFOCUS — focus callbacks to core + App notification

3. Tab.zig — Split Tree (236 lines)

Purpose

Manages the binary split tree within a single tab. Each tab has a root SplitNode that is either a leaf (single surface) or a split (two children with a direction and ratio).

Data Structures

SplitNode = union(enum) {
    leaf: *Surface,
    split: Split,
};

Split = struct {
    direction: Direction,  // .horizontal or .vertical
    ratio: f32 = 0.5,     // 0.0 to 1.0, position of divider
    first: *SplitNode,     // left or top child
    second: *SplitNode,    // right or bottom child
};

Tab = struct {
    root: *SplitNode,
    focused: *Surface,
    title: []const u8,
    alloc: Allocator,
};

Operations

FunctionComplexityDescription
init(surface)O(1)Creates a tab with a single leaf node
deinit()O(n)Frees all split nodes (not surfaces)
splitFocused(surface, dir)O(n)Finds focused leaf, replaces with split containing original + new
removeSurface(surface)O(n)Removes surface, collapses parent split. Returns false if last
layout(rect)O(n)Recursively positions all child HWNDs via MoveWindow
equalize()O(n)Recursively resets all split ratios to 0.5

Layout Algorithm

For each split node, the available rectangle is divided by the ratio along the split direction (horizontal → left/right, vertical → top/bottom). A 4px divider gap is subtracted between the two halves. Each child recursively receives its sub-rectangle. Leaf nodes call MoveWindow on their surface's child HWND and notify the core of the size change.

5. Control Flow

Startup Sequence

  1. main_ghostty.zig calls App.init()
  2. init() loads config from %LOCALAPPDATA%\ghostty\config.ghostty
  3. Creates the main window (GhosttyWindow class, WS_OVERLAPPEDWINDOW)
  4. Registers GhosttySurface child window class
  5. Stores self pointer in GWLP_USERDATA
  6. Creates search bar (EDIT + STATIC, hidden)
  7. Creates menu bar (6 popup menus)
  8. Creates first tab → creates surface → creates core surface
  9. Enters run() event loop

Event Loop

while (running) {
    GetMessageW(&msg)
    // Intercept search EDIT keys (Escape, Enter) before dispatch
    if (search_active && msg targets search EDIT) { handle; continue }
    TranslateMessage(&msg)
    DispatchMessageW(&msg)
}

Rendering Pipeline

  1. Core's renderer thread calls makeContextCurrent() → wglMakeCurrent
  2. OpenGL commands render terminal content via GenericRenderer
  3. Calls swapBuffers() → SwapBuffers(hdc)
  4. Each surface has its own GL context → multiple surfaces render independently

Input Pipeline

  1. Win32 delivers WM_KEYDOWN to focused surface's surfaceWndProc
  2. handleKeyEvent() translates scancode via translateScancode()
  3. Peeks for pending WM_CHAR to get text input
  4. Gets modifier state via GetKeyState()
  5. Calls core_surface.keyCallback() with full key event data
  6. Core processes the key (binding check → terminal write)
